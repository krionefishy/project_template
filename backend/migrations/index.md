# Migrations (Alembic)

## Инициализация (один раз при старте проекта)

`env.py` изначально **генерируется Alembic** при `alembic init`. В template он уже переписан под async-режим и загрузку конфига из YAML (как в RSD). При старте нового проекта `env.py` не трогаем — только добавляем импорты моделей.

## Управление миграциями

```bash
just db-create-migration "add users table"   # создать миграцию (autogenerate)
just db-migrate                               # применить все pending
just db-rollback                              # откатить последнюю
just db-status                               # текущий revision
just db-history                              # история
```

## Правила

1. **Никогда не редактировать** применённые миграции — только создавать новые
2. **Всегда проверять** autogenerated миграции перед коммитом — Alembic иногда генерирует лишнее
3. **Импортировать все ORM модели** в `env.py` — иначе Alembic не увидит изменения
4. Имена миграций: `<описание_на_английском>` (короткое, snake_case)

## Добавить новую ORM модель в миграции

В `env.py` добавить импорт:

```python
from backend.app.my_domain.db_models import MyModel  # noqa: F401
```

## Порядок при создании нового домена

1. Написать ORM модели в `db_models.py`
2. Импортировать в `env.py`
3. `just db-create-migration "add my_domain tables"`
4. Проверить сгенерированный файл в `versions/`
5. `just db-migrate`
